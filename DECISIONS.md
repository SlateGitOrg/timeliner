# Decisions

Rulings made during the build. Format: what was decided, why, and what it
costs if it turns out to be wrong.

- Ruling: The default zone comes from the evidence's `etc/localtime` (TZif), resolved inside the evidence root, with `etc/timezone` + host zoneinfo as fallback and UTC (flagged as "unverified") last. Why: the analyst's machine zone is irrelevant to the suspect's logs, and absolute `/etc/localtime` symlinks otherwise resolve to the analyst's own zone file. Cost if wrong: a host whose rsyslog writes UTC while `/etc/localtime` says otherwise gets a shifted timeline; the user must pass `--tz UTC`.
- Ruling: Year inference is anchored to the newest absolute timestamp from *system records* (wtmp/btmp/utmp, journal, dpkg/apt) plus one day. Shell histories anchor only when no system record has a timestamp, and the report then warns that the anchor is user-writable. The bodyfile never anchors. Why: file-system times can be timestomped or reflect collection time, and an unprivileged suspect can append any `#<epoch>` to their own history (review fix round 1: one forged line moved all syslog to 2050). Cost if wrong: evidence whose syslog continues long after every system record needs `--year`; a newer genuine history entry no longer raises the anchor when system records exist.
- Ruling: Anchor timestamps after the analysis clock + 1 day are dropped, and the largest sorted tail of ≤ 1 % of the values (at least one) lying more than 366 days after the rest is dropped as outlying. A warning (log, `(year anchor)` report warning and the year-anchor line) is raised for each rejection and when one artifact alone is more than 30 days ahead of every other anchoring artifact. Why: a max() over attacker-reachable data lets one value move the whole timeline by decades; collected evidence cannot postdate the analysis, and a genuine gap of more than a year in the newest 1 % of records is far rarer than a forged or corrupt value. Cost if wrong: a host that was idle for over a year and then had a single login (with fewer than 1 % of records after the gap) anchors to the older bulk; the warning names the dropped value and `--year` overrides it. An attacker who forges more than 1 % of the values, or forges within a year of the bulk, is not stopped by this rule alone (the tiering above covers histories).
- Ruling: With no absolute timestamps at all, the anchor is `NotAfter(analysis clock + 1 day)`, not `Explicit(current year)`. Why: `Explicit` put the newest entry of *every* file into the current year, so a rotated `auth.log.1` from December analysed in October landed in the future and after the current file (review fix round 1). The clock is a valid upper bound. Cost if wrong: evidence analysed more than ~a year after collection gets years that are too late by the elapsed whole years; the report flags the fallback and asks for `--year`.
- Ruling: `--year Y` means "the newest entry of each year-less file is in Y", not "all entries are in Y". Why: rollover inside a file is still inferred, which is what analysts expect. Cost if wrong: rotated files ending in an earlier year get the wrong year when `--year` is forced; inference (the default) handles them.
- Ruling: Year rollover = month decreases; a forward jump of ≤ 7 days across the year boundary right after a rollover is a straggler from the previous year. Why: rsyslog occasionally writes a few late lines out of order around midnight. Cost if wrong: a genuine gap of ~11 months immediately after a rollover would be assigned to the wrong year.
- Ruling: DST overlap resolves to the earlier instant and DST gap uses the pre-transition offset, both flagged on the event. Why: matches glibc `mktime(tm_isdst=-1)` and keeps ordering stable; the flags make the ambiguity visible. Cost if wrong: events in the repeated hour may be 1 h early; analysts can see `tz_ambiguous`.
- Ruling: Deduplicate by meaning (kind, host, user, description) across *different* artifacts within 2 s, never within one artifact, at most one partner per other artifact. Why: auth.log/syslog/journal/rotated copies of the same occurrence must merge, but repeated identical attempts are evidence. Cost if wrong: two genuinely distinct identical events in different files within 2 s are merged (provenance is kept in `also_seen`; `--no-dedup` disables).
- Ruling: Rules run after dedup and before the `--from/--to` filter. Why: thresholds must not double-count mirrored copies; first-seen baselines need the whole evidence. Cost if wrong: none known; filtering earlier would be faster on huge inputs.
- Ruling: `ssh-new-ip` uses `first_seen` grouped by user with `require_history: true` by default. Why: "SSH from a new IP" is only meaningful relative to an account's history; without it every account's first login fires. Cost if wrong: a compromised account with no prior login in the evidence is not flagged by this rule (other rules still fire); `--baseline-until` offers the alternative semantics.
- Ruling: dpkg.log emits events only for `install/upgrade/remove/purge`; `status/configure/trigproc/startup/conffile` are counted, not emitted. Why: a single upgrade writes ~10 state lines that add noise without new facts. Cost if wrong: an analyst interested in half-configured states must read the raw file.
- Ruling: Journal time is `_SOURCE_REALTIME_TIMESTAMP` when present, else `__REALTIME_TIMESTAMP`. Why: the source timestamp reflects when the message was produced rather than when journald received it. Cost if wrong: sub-second differences against syslog copies; absorbed by the dedup window.
- Ruling: Use the `serde_yaml` 0.9 crate (upstream marked deprecated) for the rule files. Why: it is stable, already vendored in the local cache, and rule files are a tiny trusted-by-the-analyst input; behaviour is pinned by `Cargo.lock`. Cost if wrong: a future migration to a maintained fork (`serde_norway`/`serde_yml`) is a one-line change plus re-test.
- Ruling: All outputs are UTC; no display zone option. Why: one unambiguous clock across tools (plaso, timesketch) and reproducible reports. Cost if wrong: analysts who think in local time must convert mentally; roadmap item.
- Ruling: CSV/l2tcsv neutralize spreadsheet formulas by default (prefix `'` to attacker-influenced cells starting with `= + - @ TAB CR` and longer than one char). Why: log fields such as usernames are attacker-controlled and analysts open CSVs in spreadsheets. Cost if wrong: such cells differ from the raw value by one leading quote; `--no-csv-safe` restores raw output.
- Ruling: The fixture user `sysbackup` is created with `/usr/bin/fish` as its shell. Why: so that the committed evidence exercises every history parser (bash, zsh, fish) in one story. Cost if wrong: slightly less typical attacker behaviour in the synthetic story; it does not affect parser correctness.
- Ruling: The fixture's `etc/localtime` is committed as an absolute symlink to `usr/share/zoneinfo/America/New_York` inside the evidence tree, and that file is a generated TZif equivalent to the New York rules (2023–2024 transitions + POSIX footer), not a copy of the IANA file. Why: exercises re-rooting of absolute symlinks and the TZif footer path while keeping all data self-generated. Cost if wrong: on a non-symlink-capable checkout (Windows) the zone falls back to UTC and the story test fails; CI targets Linux and macOS only.
